# 关键词问答（问股）头脑风暴

> 需求：用户输入个股/概念题材关键词 → 智能体分析意图 → 实时抓取韭研公社 24h 内相关资讯 → 关联过滤、抽取合并 → 结论呈现。
> 定位：与现有「定时批处理推送」互补的**按需问答智能体**。
> 本文是发现期头脑风暴，配合后续技术方案食用；代码事实基于 v2 流水线现状。

## 0. 已确认的产品决策（2026-11-10）

| 决策点 | 选择 | 影响 |
|---|---|---|
| 交互入口 | **Web 站内对话页**（新增 `/ask`） | 复用 React Router v7 应用 + SQLite 直读，不新建 bot/CLI 交付面 |
| 数据获取 | **每次全量实时爬**（12 板块） | 单次查询 2-4 分钟等待，进度可视化成为体验关键项 |
| 澄清交互 | **一次出结果 + 假设说明** | 无对话状态机；意图理解透明化 + 事后修正 chips 补准确率 |
| 内容深度 | **摘要为主，高价值帖抓全文** | 需新增 `/a/{id}` 详情页抓取能力（现有 items 仅 600 字截断摘要） |

技术前提（决定设计形状的硬约束）：
- 韭研公社**无站内搜索 API**（官方 JSON API 需 token 已放弃），"到网站搜索" = 实时爬 12 板块页 → 本地关键词过滤。
- SSR 列表页无分页，每板块固定 ~30 条；去重主键 `/a/{id}` URL，重复爬取幂等。
- LLM 走智谱 GLM（`packages/llm/src/client.ts`），无 key 时 handoff 落盘降级；prompt 全外置 `industry/prompts/`。

## 1. 三视角 Idea 池

### 1.1 产品经理视角（价值创造 / 验证速度 / 差异化）

| # | Idea | 一句话价值 |
|---|---|---|
| PM1 | **「问股」核心 MVP**：关键词 → 结论先行卡片（一句话结论 + 关联度 + 时间线 + 涉及个股 + 证据链） | 直接交付需求全部四条，产品价值锚点 |
| PM2 | **意图假设透明化**：结果页首行展示"我理解你想了解 X 的催化逻辑"+ 关键词扩展明细（股票别名/上下游概念），可纠正 | 低成本弥补"无澄清对话"的准确率风险，建立信任 |
| PM3 | **查询↔题材联动**：结论卡附带该关键词命中的当日题材综述（复用 themes 表） | 打通按需问答与定时推送两个产品面，普通搜索做不到 |
| PM4 | **订阅追踪（二期）**：查询后一键订阅关键词，后续爬取轮次增量推送飞书 | 复用 push 基础设施，一次性查询变持续价值 |
| PM5 | **无结果兜底**：24h 无命中自动扩窗 48/72h 并明确标注 + 给最接近的关联题材 | 管理预期，避免空手而归导致流失 |

### 1.2 产品设计师视角（体验 / 预期管理 / 信任）

| # | Idea | 一句话价值 |
|---|---|---|
| D1 | **结论先行答案卡**：加粗一句话结论 → 关键信息点（每点带来源链接）→ 个股 chips → 时间线 | 延续 write 阶段"答案先行"哲学与三列高密度卡片审美 |
| D2 | **分步进度可视化**：SSE 实时推送五步（理解意图 → 实时抓取 → 关联筛选 → 深挖全文 → 综合结论），每步带计数 | 实时爬取 2-4 分钟是最大弃用风险，进度是体验救生圈 |
| D3 | **意图修正 chips**：结果页顶部 2-3 个"你是不是想问"候选（如：固态电池·产业催化 / ·个股名单 / ·情绪热度），点击带修正意图重跑 | 不做多轮对话状态机，却拿到澄清的大部分收益 |

### 1.3 软件工程师视角（架构 / 复用 / 风险）

| # | Idea | 一句话价值 |
|---|---|---|
| E1 | **ask 链路同构现有阶段**：新增 ask 阶段（scripts/ask.ts + stages/ask.ts），prompt 外置 `ask-intent.md` / `ask-relevance.md` / `ask-synthesize.md`，复用 GLM client + handoff 降级 | 零新框架，维护心智与现有 7 阶段一致 |
| E2 | **关键词扩展三路召回**：① SQL 匹配（标题/摘要/stocks/tags）② taxonomy `conceptKeywords` 别名 ③ LLM 意图分析产出扩展词（代码/简称/别称/上下游），并集去重后进 LLM 关联过滤 | 召回质量的决定因素；纯 LIKE 匹配召回不了"宁王"→宁德时代 |
| E3 | **爬取复用 + 短窗缓存锁**：crawl 已支持 `--boards`，加"15 分钟内爬过则跳过重爬"的防抖锁；爬完 upsert 入 SQLite，查询侧统一从 DB 读 | 既尊重"每次实时爬"决策，又防连点/并发把站点打爆 |

| E5 | **详情页全文按需抓取**：`packages/sources` 新增 fetchDetail(`/{id}`)，仅对 LLM 判定高关联的 Top 3-5 帖抓全文，回填 `items.detail` 缓存复用 | 分析质量的跃迁点，抓取量可控 |
| E6 | **任务编排与并发**：单飞（in-flight 锁）同关键词查询合并、结果互斥写 `ask_results`、SSE 断线可重连续传 | 长任务的工程完备性，防重复计费/重复爬取 |

## 2. Top 5 优先级（验证导向：核心价值 > 快速验证 > 差异化）

### P1 · 问股核心链路（PM1 + E1 + E2）
意图分析 → 关键词扩展三路召回 → 实时爬取入库 → LLM 关联过滤 → 抽取合并综合 → 结论卡。
**理由**：交付需求四条的全部；无此则其余皆无意义。E2 是其中技术风险最高的一环，必须与链路同批验证。
**待验证假设**：
- 12 板块 × ~30 条 × 24h 语料（≈ 300-500 帖，去重后）足以回答 80% 的个股/题材查询
- GLM 意图扩展的准确率可接受（别名/上下游词不发散、不跑偏）

### P2 · SSE 分步进度（D2 + E4）
**理由**："每次实时爬"决策下 2-4 分钟等待是最大体验风险；SSE 同时是后续流式输出的技术底座。
**待验证假设**：有进度反馈时用户可接受 2-4 分钟（弃用率可观测）。

### P3 · 证据溯源 + 意图透明（D5 + PM2）
**理由**：投研场景无来源 = 不可信 = 不可用；意图透明是"一次出结果"决策的准确率保险。
**待验证假设**：来源展开/点击率 > 20% 说明信任成立；意图修正请求率 < 30% 说明意图分析达标。

### P4 · 高价值帖全文深挖（E5，已确认决策）
**理由**：600 字截断会丢长帖的数据与逻辑链；限 Top 3-5 帖抓取，站点压力可控。
**待验证假设**：全文对结论质量的提升可感知（同关键词开/关全文 A/B 对比）。

### P5 · 意图修正 chips + 无结果兜底（D3 + PM5）
**理由**：低成本高杠杆的准确率补救与空结果防流失，都挂在 P1 的产出结构上，增量小。
**待验证假设**：修正 chips 使用率 < 10% 即可移除投入，说明意图分析已够准。

**二期池**（本期不做）：PM3 题材联动深化、PM4 订阅追踪推送、D4 热门榜、E6 完整并发编排（先做最小单飞锁）。

| 阶段 | 内容 | 验收 |

## 4. 开放问题（进技术方案前需定）

1. 爬取防抖窗口具体值（建议 15 分钟，可配）与并发单飞锁的范围（同关键词 or 全局）。
2. `ask_results` 表结构：是否存完整中间产物（扩展词、候选集、过滤结果）便于复盘调 prompt。
3. 模型分工：intent/relevance 用 `glm-4-flash`（快、便宜），synthesize 是否上更强模型（质量 vs 成本）。
4. 详情页解析的健壮性：`/a/{id}` 页面结构无 fixture 护航，需按 sources 现有 `selectors.ts` + 快照回归模式补。
5. 24h 窗口的语义：自然日、滚动 24h、还是"最近一轮爬取回溯 24h"（建议滚动 24h，与 hot 页一致）。
