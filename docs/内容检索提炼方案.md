# 内容检索提炼方案

> 回答两个问题：**从哪里抓、怎么抓（检索）？怎么从噪声里提炼出值得看的信息（提炼）？**
> 代码入口：`packages/sources/`（检索）· `packages/core/src/stages/`（提炼）· `industry/prompts/`（提示词）

## 1. 检索（采集）

### 1.1 信源策略

| 项 | 决策 | 原因 |
|---|---|---|
| 数据源 | 韭研公社 SSR 网页（`square_*/study_*/live_*` × publish/hot/action/30 共 12 板块页/轮） | robots.txt 全放行、匿名可达；JSON API 需 token + 地域限制，放弃 |
| 抓取节奏 | 每日 3 轮（随推送时段），轮内 2-5s 随机间隔 | 覆盖"重要资讯"足够；高频抓取对 UGC 社区增益小 |
| 单轮容量 | 每板块 30 条（SSR 无分页，`?page=` 无效） | 已验证；扩量需逆向客户端 API（演进项） |
| 去重主键 | `/a/{id}` URL | 帖子唯一标识，跨板块出现自动合并 |
| 详情页全文 | 对 **selected** 帖子抓 `/a/{id}` 正文存 `item_details`（detail 阶段，每轮 ≤50 条；正文在 `window.__NUXT__` 载荷 content 字段，VM 沙箱求值提取，纯文本截 8000 字） | 列表页摘要仅 600 字不够写作与检索；抓过不重抓（失败也留行防反复重抓，`--retry` 清失败行）；长文分页只是评论区，首屏即全量正文。与 /ask 问答功能共用缓存 |
| 降级规则 | 置顶官方帖（无时间）不入库；纯图帖保留（靠标题打分）；板块解析 0 条 = 告警 | 无可信发布时间的条目不参与（AIHOT 同款） |
| 改版应对 | 选择器集中 `selectors.ts` + `__fixtures__` 快照回归 + `inspect-fixture` 探测工具 | 站点改版 → 跑工具 → 改选择器 → 测试护航 |

### 1.2 多信源扩展

实现 `SourceAdapter` 接口（`crawl(ctx) → items`）并在 `loader.ts` 注册、`industry/sources.json` 加配置即可；下游（预筛/打分/聚簇/题材/推送/网站）全部复用。候选：财联社电报（json_list 型）、雪球热帖（web_list 型）。

## 2. 提炼（四层去噪）

### 2.1 预筛 prefilter（纯规则，宽进严拦）

按序：拦截关键词（广告/引流）→ 旧文归档（>48h，见[新鲜度方案](新鲜度方案.md)）→ 近似去重（标题归一化 2-gram Jaccard ≥0.72，比对 14 天池 + 本批内部；**同作者系列帖豁免**，如"盘前纪要"日更交给聚簇）。候选上限 80/轮，按互动参与度（赞1/评4/转3）排序，重复中强者存活。

### 2.2 打分 score（LLM 双次独立）

- 同一标准独立打两次 0-100（handoff 模式一次产出 score1/score2 且禁止照抄，分差 >15 复核）；过分级门槛（见[资讯分类方案](资讯分类方案.md) §2）
- **评分锚点**：题材/产业链事件 85+ / 个股深度与情绪复盘 70-84 / 常规内容 50-69 / 低价值 30-49 / 噪声 0-29
- **信息增量规则**：同一事件后续跟进帖无新信息则显著压分（实测：跟风帖大量落在 55-68 被拦）
- 随打分产出结构化标签：industry / concepts(≤3) / driver 九分类
- 提示词：`industry/prompts/score.md`（**想调"什么算重要"，改这一个文件**）

### 2.3 聚簇 cluster（规则候选 + LLM 复核）

- 候选对（48h 窗口）：标题 Jaccard ≥0.5；或 股票重叠 且标题 ≥0.25；或 概念重叠且同行业——**股票重叠单独不成立**（标签传递会连锁扩散，实测曾把 14 帖连成一组）
- 并查集成组；超大组（>6）退化为"直接邻接"（最高分成员为种子）
- LLM 逐组复核：判"同一具体事件或同一题材催化"，**拿不准判 false，宁分勿合**（一周实践约 70% 组被否决；true 集中在"同标的同进展线"）
- 代表帖：分数最高 → T1_5 → 更早发布
- 已知约束：组内含已归属其他事件的成员时禁 true（commitGroup 双挂缺陷，技术方案 §技术债）

### 2.4 写作 write（LLM）

答案先行摘要（2-3 句 ≤120 字：结论→驱动与边际变化→参与提示）+ 推荐理由一句 + 事件标题 ≤20 字；禁止编造，信息不足写"待验证"。提示词：`industry/prompts/write.md`。

### 2.5 题材综述 theme（LLM）

见[资讯分类方案](资讯分类方案.md) §4。提示词：`industry/prompts/theme.md`。

## 3. 提示词清单（know-how 外置，全部在 industry/prompts/）

| 文件 | 阶段 | 产出 | 调整场景 |
|---|---|---|---|
| score.md | score | 双次打分 + 结构化标签 | 调"什么算重要" |
| cluster-review.md | cluster | 组是否同一事件 | 调合并松紧 |
| write.md | write | 事件摘要 + 推荐理由 | 调摘要风格/长度 |
| theme.md | theme | 题材催化逻辑综述 | 调综述口径 |

改提示词不需要改代码；handoff 与 API 模式共用同一份。

## 4. 质量校准（规划）

AIHOT SelectBots 路线：积累 100-200 条人工金标 → 门槛扫描（40-90 每 2 分一档）→ 先改提示词标准、再动数值门槛 → 开发/留出集分离防过拟合。当前以运行观察 + 手动校准为主。
