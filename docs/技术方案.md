## 3. LLM 双模式与 handoff 协议

模式：设 `GLM_API_KEY` → 直调智谱（`GLM_MODEL_SCORE/CLUSTER/WRITE/THEME` 分阶段配模型，默认 glm-4-flash）；未设 → handoff。

协议流程：阶段 CLI 生成 `data/llm-tasks/<stage>-<batch>.json`（prompt 全文 + input + outputFile）→ agent 按任务内提示词产出 `data/llm-results/<同名>.json`（`{version,stage,batch,outputs}`）→ `--consume` 做 schema + id/batch 一致性校验后入库并删任务。

**铁律（实战沉淀，校验已兜底）**：outputs 的 id/groupId/eventId/themeId 与 batch 必须原样复制；打分中断会使聚簇任务基于不完整集合——删任务重跑。

## 4. 数据模型（SQLite → Postgres 兼容）

| 表 | 说明 |
|---|---|
| items | 条目主表；状态机 new→candidate→selected/rejected（旁路 blocked/archived_old） |
| events | 事件：summary/reason、heat/prev_heat、member_count、pushed_at |
| event_members | 事件-条目（representative/member） |
| themes | 题材：按（北京日期,分类）每次 theme 阶段重建；logic 综述、top_stocks、heat_total |
| pushes | 推送历史（增量游标 + payload 审计） |
| runs / sources | 阶段可观测性 / 信源注册 |

迁移文件即 schema 文档：`database/migrations/0001_init.sql`、`0002_themes.sql`。

## 9. 演进路线

1. **生产化**：VPS + Docker（web/worker/postgres）→ SQLite 迁 PG → pg-boss 调度 → GLM API 直调去 handoff
2. **多信源**：财联社/雪球适配器，跨源聚簇
3. **校准**：金标集 + 门槛扫描；题材概念二级子簇
4. **write 增强**：合并事件摘要增量重写
