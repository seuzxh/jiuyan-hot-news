# 新鲜度方案

> 系统内所有与"时间"有关的规则集中在此：什么算旧、热度怎么衰减、推送怎么增量、题材怎么滚动、网站怎么按日期看。

## 1. 时间基准

- 存储：ISO8601 **UTC**（`items.published_at` 等）
- 展示/分槽：统一转**北京时区**（`bjTime`/`bjDateKey`/`currentSlot`，core/time.ts）
- 时段划分：05-11 早报 / 12-15 午报 / 其余晚报（`currentSlot`）

## 2. 条目级：旧文不刷屏

| 规则 | 参数 | 位置 |
|---|---|---|
| 首见距发布 >48h → 只归档（`archived_old`），不进当天、不参与打分 | `PREFILTER.oldItemHours = 48` | industry/selection.ts |
| 无可信发布时间的条目（置顶官方帖、相对时间未展开）→ 不入库 | 采集阶段 | parse.ts |
| 近似去重回看窗口 14 天 | `nearDupWindowHours` | 同上 |

**为什么 48h**：与热度窗口对齐——超过热度窗口的旧帖即使混进来也不产生热度，但会在推送/网站占据位置，直接归档最干净。

## 3. 热度衰减（按事件算）

```
heat = Σ 成员帖 (赞×1 + 评×4 + 转×3)
     · 仅计 published_at 在 48h 内的成员（窗口外不计）
     · 超 24h 的成员贡献 ×0.5
```

- **每帖只计一次**：防单帖/单作者刷屏（AIHOT 同款）
- `prev_heat` 保留上一轮值，供网站"涨"标记（heat > prev×1.3）
- 配置：`industry/selection.ts` 的 `HEAT`

## 4. 题材滚动窗口

- theme 阶段每次运行取 `last_item_at ≥ now-24h` 的事件聚题材
- 当日题材**整表重建**（`DELETE + INSERT`，按北京日期 key）——综述随每轮推送刷新，历史日期保留可回溯
- 单事件题材不生成 LLM 综述

## 5. 推送增量语义

| 项 | 规则 |
|---|---|
| 增量定义 | `last_item_at > since` 且（未推送过 或 推送早于最后一次新帖）的事件——即"有新内容的事件" |
| since | 默认上次成功推送时间；首次/补发用 `--since-hours=N` 覆盖 |
| 失败安全 | 推送失败不写 pushes、不置 pushed_at → 事件不丢，下次自动补 |
| 每轮上限 | 12 事件 → 题材卡呈现 ≤5 题材 × 3 事件 + 其他动态 ≤3 |
| 频率 | 每日 3 推（08:00/12:00/20:00 北京时间） |

**有意的设计取舍**：同一事件有新帖时会再次出现（"另有 N 帖"数字更新），但纯旧事件不会重复轰炸；被挤出的低热度事件在网站完整可查。

## 6. 网站侧

- 首页**日期切换条**（今天/昨天/N 月 N 日 + 当日事件数），按北京日期分组，默认最新一天——新旧一目了然
- 卡片左上角带发布时间（MM-DD HH:mm 北京时间）
- "新"标记：事件创建 <12h；"涨"标记：热度较上轮涨 30%+
- 热点榜只取 48h 内事件（与热度窗口一致）

## 7. 已知问题

- 事件合并进新帖后摘要不自动重写（write 只处理 `summary IS NULL`）——综述可能滞后于成员变化（技术债 #2）
- 题材综述每轮全量重写（LLM 成本可接受，但无 diff 感知）
- 调整入口统一在 `industry/selection.ts`（ PREFILTER/HEAT/THRESHOLDS）与 `scripts/push.ts`（卡片上限）
