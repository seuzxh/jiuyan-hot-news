# 资讯分类方案

> 回答四个问题：**这条资讯值不值得入选？属于什么分类？它和哪些资讯讲的是同一条逻辑？这条逻辑链上谁站在哪一环？**
> 代码入口：`packages/core/src/taxonomy.ts`（展示分类）· `packages/core/src/stages/concepts.ts`（概念归一化）· `industry/selection.ts`（门槛）· `industry/prompts/concept.md`（归类与逻辑卡写作）

## 1. 三级内容层级

```
条目 item（一篇帖子）
  └─ 事件 event（同一具体事件的多篇帖子合一，代表帖出面）
       └─ 概念 concept（同一条产业逻辑链的多篇帖子：结论 + 因果链 + 标的角色 + 风险）
```

- 条目 → 事件：聚簇阶段（见[内容检索提炼方案](内容检索提炼方案.md) §2.3）
- 事件 → 概念：concept 阶段，LLM 按"产业逻辑链"归类，每次推送前用 24h 窗口重建当日逻辑卡
- 帖子与概念是**多对多**：一篇盘前纪要会同时是"具身大脑""PCB 缺货""黄仁勋复职"几条逻辑线的素材

**为什么单位是概念而不是帖子**：读者要的是"这条逻辑走到哪一步、谁在链条的哪一环"，而不是"今天有哪些帖子"。汇总帖（盘前纪要、学习笔记、热度汇总）本身不是一条逻辑，它里面的话题要拆开归位。

## 2. 入选门槛（分级）

| 级别 | 判定依据（作者徽章） | 门槛 | 依据 |
|---|---|---|---|
| T1_5 | 机构 / 游资 / 公社达人 / 大神等 | 双次打分均分 ≥ **65** | 准官方信源，历史质量高 |
| T2 | 普通用户（含无徽章） | 双次打分均分 ≥ **76** | 偏严：宁少勿滥 |

- 双次独立打分取均值过线（AIHOT 同款，抑制单次抖动）
- **政策与宏观类默认压 15 分**（部委政策/央行动向/宏观数据/外围市场），除非直接改变板块预期
- 配置位置：`industry/selection.ts` 的 `THRESHOLDS`

### 3.1 判定算法：概念关键词加权计分

优先级：**概念计分 > 驱动类型 > 行业 > 其他**

```
score(分类) = Σ 关键词长度（对每个命中标签累加，越长越具体权重越高）
```

为什么不用简单子串匹配：`"物理AI"` 包含 `"AI"`，会把 Optimus 事件误归 AI 类。加权后：
- 机器人事件 tags=[人形机器人,Optimus,物理AI]：robot 得 3+7+3=13 分，ai 仅 2 分 → robot ✓
- `"太空算力"`(4字) 归 AI·算力（4>2 压过 space 的 `"太空"`），`"太空光伏"`(4字) 归新能源 ✓
- 裸 `"IP"` 不作为关键词（`"iPSC"` 含 `IP` 子串曾误归传媒），只收 `IP改编/IP运营/IP储备`

### 3.2 调整方法

改 `packages/core/src/taxonomy.ts` 的 `CATEGORIES`（label/emoji/keywords/industries），跑 `npm test` 里的 taxonomy 用例回归。这份类目在三处共用：网站的帖子视图、飞书兜底事件卡、概念卡的 `category`（由 LLM 从这份类目里选；选错或缺失时按成员事件的标签兜底）。

## 4. 概念逻辑卡（concept 阶段）

**输入**：窗口内全部事件（标题、摘要、正文节选 ≤1500 字、标的、标签、热度、时间），最多 40 个（按热度取）。
**输出**：若干张逻辑卡（通常 3–15 张，视当日信息密度）。

### 4.1 归类规则

1. **看逻辑，不看体裁**：盘前纪要、调研、复盘、信息差都只是素材，讲同一条逻辑链的信息归到同一个概念
2. **汇总帖要拆开**：汇总帖提到的话题分别挂到各自的概念上
3. **粒度 = 一条能独立讲清楚的逻辑链**（如"PCB 缺货""光刻胶国产替代""具身智能数据""两融松绑"）：不粗到"AI""机器人"整条赛道，也不细到只讲一家公司
4. **每个帖子至少归入一个概念**；没被覆盖的由代码兜底成"其他动态"，保证推送和站点不丢信息

### 4.2 逻辑卡字段

| 字段 | 含义 | 上限 |
|---|---|---|
| `title` | 概念名，写成逻辑而不是栏目名 | 16 字 |
| `category` | taxonomy 分类 id | — |
| `takeaway` | 一句话结论：这条逻辑现在处于什么状态、边际变化是什么 | 64 字 |
| `chain` | 因果链环节，从催化写到受益环节，每环要能看出为什么传导到下一环 | 6 环 × 40 字 |
| `stocks` | 核心标的及其在链条中的环节/角色 | 8 个（角色 16 字） |
| `risk` | 传闻未证实、数据口径、多空分歧、退潮信号 | 90 字 |
| `eventIds` | 支撑该概念的帖子（多对多） | — |

### 4.3 写作纪律

- **只依据输入里的事实**：数字、日期、政策、订单必须来自输入帖子；可以推理传导关系，但不得新增事实，事实与推断分开表述
- **判断以正文为准**：摘要只是索引，标的角色、数字和催化时点都在正文节选里（同一批素材，只读摘要会漏掉"刚果钴矿禁令"这类整条逻辑线）
- 标的角色以帖子给出的定位为准；帖子只点了板块没点名公司时，可补充该环节公认的龙头（≤3 个），角色以"补充·"开头，让读者分得清哪些是来源点名、哪些是分析补充
- 多个来源讲同一件事时合并去重；来源冲突写进 `risk`
- 不照搬帖子标题和摘要句式，不写来源标注，不罗列"发生了什么"

### 4.4 排序

情绪/盘面与"其他"垫底；其余按"有多少帖子在讲"降序，同帖数看热度合计。不用热度合计做主排序——汇总帖热度高且同时属于多个概念，会让排序偏置。

存储：`concepts` 表按北京日期整日重建（见[新鲜度方案](新鲜度方案.md) §4）。

## 5. 推送呈现

飞书卡片以逻辑线为单位（每条 = 结论 + 因果链 + 标的角色 + 风险），只推含新增帖子的概念：

```
🦾 具身大脑跃迁  [新] [7帖]
结论：FSD V15 与 GPT-6.2 接连验证通用模型落到真机，具身大脑出现可测量的能力拐点
逻辑：FSD V15 的视觉编码器改为三线共用 → 数百万互联网视频训练的感知能力可跨场景复用 → GPT-6.2 操控双臂成功率升至 41.2% → 大脑不再是唯一瓶颈，验证点转向数据与量产
🎯 上纬新材·本体·大脑协同 ｜ 宇树科技·训练本体平台 ｜ 联创电子·车载视觉镜头
⚠️ 彭博专栏提醒大量演示含远程操控或预编程成分，商业化节奏或被高估
```

## 6. 已知边界

- 归类与写作质量取决于 LLM；handoff 模式下由定时任务里的 agent 按 `industry/prompts/concept.md` 完成
- 历史日期不会自动有逻辑卡，需 `npm run concept -- --date=YYYY-MM-DD` 回填（目前已回填 11-23、11-24）；未回填的日期网站回退到帖子视图
- 概念不跨轮保持身份：每轮整日重建，推送里的"新/更新"按成员帖是否推送过来判断
